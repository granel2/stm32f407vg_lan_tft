# Display — 3.5" ST7796S TFT (320×480), 4-wire SPI

Самодостаточный модуль: весь код и вся документация по дисплею лежат здесь, отдельно
от Ethernet/lwIP-части в `Core/`. Задуман так, чтобы дальнейшую доработку экрана
(шрифты, экран сетевого статуса, новые виджеты) можно было вести, трогая только эту
папку — `main.c` знает только о трёх функциях (см. «Слои кода» ниже).

## Структура

| Путь | Что это |
|---|---|
| `Inc/st7796s.h`, `Src/st7796s.c` | Низкоуровневый драйвер контроллера ST7796S: init-последовательность, RAMWR/CASET/RASET, заливки, поворот (MADCTL), примитив 7-сегментных цифр. Не знает ни о плате, ни о приложении. |
| `Inc/tft_app.h`, `Src/tft_app.c` | Прикладной слой: владеет `hspi3`, настраивает SPI3 и GPIO CS/DC/RST/BL, решает, что и когда рисовать (boot-смоук-тест, live-счётчики). **Это файл для доработки** — новые экраны/виджеты добавлять сюда. |
| `docs/TFT_WIRING.md` | Пины модуля ↔ STM32 ↔ разъёмы платы (SV4 + SV1), проверка перед включением. |
| `docs/TFT_3.5_board.md` | Описание платы-адаптера дисплея: разъёмы 40-pin FPC/8080-8P/8080-16P/9-pin SPI, таблица перемычек IM0–IM2, питание (LDO U8, транзистор подсветки U7). |
| `docs/display_3.5_tft_front.jpg` | Фото модуля спереди. |
| `docs/tft_board_back.jpg` | Фото платы-адаптера сзади — читаемая ориентация, с таблицей перемычек IM. |

## Слои кода

```
main.c
  │  TFT_App_GPIO_Init()   — сразу после MX_GPIO_Init(), до всего остального
  │  TFT_App_SPI3_Init()   ─┐  один раз при старте, до MX_LWIP_Init() —
  │  TFT_App_SmokeTest()   ─┘  блокирующие HAL_Delay() не должны стопорить DHCP/ETH
  │  TFT_App_AlivePoll()   — каждую итерацию while(1), сам ограничивает себя 1 Гц
  ▼
Display/Src/tft_app.c  (прикладной слой, PC10/11/12 + PA15/PA4/PB8/PB9)
  ▼
Display/Src/st7796s.c  (низкоуровневый драйвер контроллера)
```

`Debug_Print()` (лог в USART1) остался в `main.c`, объявлен в `main.h` — им пользуются
и Ethernet-код, и `tft_app.c`.

## Подключение — коротко

9-контактный разъём SPI на плате-адаптере → плата f407, всего **2 разъёма** (SV4 + SV1) —
DC/RST перенесены с SV5 на SV1, рядом с BL, чтобы не тянуть провода к третьему разъёму
(подробности и проверка перед включением — в [`docs/TFT_WIRING.md`](docs/TFT_WIRING.md)):

| Модуль (9-pin SPI) | STM32 | Разъём платы |
|---|---|---|
| GND | GND | SV4.6 |
| VCC | +5V (если на модуле есть LDO) / +3V3 | SV4.5 / SV2.1 |
| SCL | PC10 SPI3_SCK | SV4.3 |
| SDA | PC12 SPI3_MOSI | SV4.1 |
| SDA-O | PC11 SPI3_MISO | SV4.2 (нужен только для чтения ID) |
| CS | PA15 (GPIO) | SV4.4 |
| BL | PB8 (1 = вкл) | SV1.3 |
| RST | PB9 | SV1.4 |
| DC | PA4 | SV1.5 |

BL/RST/DC — три соседних пина SV1 (3/4/5), компактный жгут из трёх проводов. PA4/PB9 на
этой плате подписаны как DAC_OUT1/RPM2 (см. `hardware/BOARD.md`), но в прошивке не заняты
ничем — тот же случай, что и PB8 под BL.

**Перемычки IM0/IM1/IM2 на плате-адаптере** должны стоять в положении **SPI (4-wire)**
= `IM2=1, IM1=1, IM0=1`. **Проверено по фото `docs/tft_board_back.jpg`: на этом
экземпляре уже впаяны в `1/1/1`** — режим SPI, перепаивать не требуется. Таблица
режимов — в [`docs/TFT_3.5_board.md`](docs/TFT_3.5_board.md).

## Известный открытый вопрос: контроллер ST7796S или ILI9488?

Плата-адаптер не подписана; по разводке 40-pin FPC она совпадает и с ST7796S, и с
ILI9488. Драйвер (`st7796s.c`) целиком написан под ST7796S — командный набор
разблокировки (`0xF0/0xC3/0x96`), таблицы гаммы (`0xE0/0xE1`), `COLMOD=0x55`
(16 бит/пиксель). Для настоящего ILI9488 по SPI это, как правило, **не сработает
корректно** — тот обычно не принимает 16bpp по последовательному интерфейсу и требует
18bpp (`COLMOD=0x66`, 3 байта/пиксель), да и часть регистров инициализации у него другая.

Проверка — при каждом старте `TFT_App_SmokeTest()` печатает в USART1 (921600 baud):

```
[tft] RDID4(0xD3) = xx 00 77 96 -> ST7796S confirmed
```

Если вместо `00 77 96` приходит что-то около `00 94 88` — это ILI9488, и `st7796s.c`
нужно будет доработать под него отдельной веткой инициализации.
