# Display — 3.5" ST7796S TFT (320×480), 4-wire SPI

Самодостаточный модуль: весь код и вся документация по дисплею лежат здесь, отдельно
от Ethernet/lwIP-части в `Core/`. Задуман так, чтобы дальнейшую доработку экрана
(новые виджеты, другие экраны) можно было вести, трогая только эту папку — `main.c`
знает только о четырёх функциях (см. «Слои кода» ниже).

## Структура

| Путь | Что это |
|---|---|
| `Inc/st7796s.h`, `Src/st7796s.c` | Низкоуровневый драйвер контроллера ST7796S: init-последовательность, RAMWR/CASET/RASET, заливки, поворот (MADCTL), примитив 7-сегментных цифр, битмап-шрифт 5x7 (`ST7796S_DrawChar`/`DrawString`). Не знает ни о плате, ни о приложении. |
| `Inc/tft_app.h`, `Src/tft_app.c` | Прикладной слой: владеет `hspi3`, настраивает SPI3 и GPIO CS/DC/RST/BL, решает, что и когда рисовать (boot-смоук-тест, экран сетевого статуса). **Это файл для доработки** — новые экраны/виджеты добавлять сюда. |
| `docs/TFT_WIRING.md` | Пины модуля ↔ STM32 ↔ разъёмы платы (SV4 + SV1), проверка перед включением. |
| `docs/TFT_3.5_board.md` | Описание платы-адаптера дисплея: разъёмы 40-pin FPC/8080-8P/8080-16P/9-pin SPI, таблица перемычек IM0–IM2, питание (LDO U8, транзистор подсветки U7). |
| `docs/display_3.5_tft_front.jpg` | Фото модуля спереди. |
| `docs/tft_board_back.jpg` | Фото платы-адаптера сзади — читаемая ориентация, с таблицей перемычек IM. |

## Слои кода

```
main.c
  │  TFT_App_GPIO_Init()                        — сразу после MX_GPIO_Init(), до всего остального
  │  TFT_App_SPI3_Init()                       ─┐  один раз при старте, до MX_LWIP_Init() —
  │  TFT_App_SmokeTest()                       ─┘  блокирующие HAL_Delay() не должны стопорить DHCP/ETH
  │  TFT_App_AlivePoll(ip_str, link_up, tcp)   — каждую итерацию while(1), сам ограничивает себя 1 Гц;
  │                                               main.c передаёт то же состояние netif/TCP, что уже
  │                                               считает для UART-heartbeat
  ▼
Display/Src/tft_app.c  (прикладной слой, PC10/11/12 + PA15/PC7/PD5/PD6)
  ▼
Display/Src/st7796s.c  (низкоуровневый драйвер контроллера)
```

`Debug_Print()` (лог в USART1) остался в `main.c`, объявлен в `main.h` — им пользуются
и Ethernet-код, и `tft_app.c`.

## Подключение — коротко

9-контактный разъём SPI на плате-адаптере → плата f407, всего **2 разъёма** (SV4 + SV1) —
DC/RST/BL сгруппированы на SV1, чтобы не тянуть провода к третьему разъёму
(подробности и проверка перед включением — в [`docs/TFT_WIRING.md`](docs/TFT_WIRING.md)):

| Модуль (9-pin SPI) | STM32 | Разъём платы |
|---|---|---|
| GND | GND | SV4.6 |
| VCC | +5V (если на модуле есть LDO) / +3V3 | SV4.5 / SV2.1 |
| SCL | PC10 SPI3_SCK | SV4.3 |
| SDA | PC12 SPI3_MOSI | SV4.1 |
| SDA-O | PC11 SPI3_MISO | SV4.2 (нужен только для чтения ID) |
| CS | PA15 (GPIO) | SV4.4 |
| BL | PC7 (1 = вкл) | SV1.8 |
| RST | PD5 | SV1.9 |
| DC | PD6 | SV1.10 |

BL/RST/DC — три соседних пина SV1 (8/9/10), компактный жгут из трёх проводов. PC7/PD5/PD6
на этой плате подписаны как USART6/USART2 TX-RX (см. `hardware/BOARD.md`), но ни один из
этих UART в прошивке не занят — тот же случай, что и раньше с PB8 под BL. PC7 сидит на
порту GPIOC, который иначе в проекте не включается — `TFT_App_GPIO_Init()` сам включает
его тактирование.

**Перемычки IM0/IM1/IM2 на плате-адаптере** должны стоять в положении **SPI (4-wire)**
= `IM2=1, IM1=1, IM0=1`. **Проверено по фото `docs/tft_board_back.jpg`: на этом
экземпляре уже впаяны в `1/1/1`** — режим SPI, перепаивать не требуется. Таблица
режимов — в [`docs/TFT_3.5_board.md`](docs/TFT_3.5_board.md).

## Контроллер: ST7796S (подтверждено косвенно, RDID4 ненадёжен)

Плата-адаптер не подписана; по разводке 40-pin FPC она совпадает и с ST7796S, и с
ILI9488. Драйвер (`st7796s.c`) целиком написан под ST7796S — командный набор
разблокировки (`0xF0/0xC3/0x96`), таблицы гаммы (`0xE0/0xE1`), `COLMOD=0x55`
(16 бит/пиксель). Для настоящего ILI9488 по SPI это, как правило, **не сработает
корректно** — тот обычно не принимает 16bpp по последовательному интерфейсу и требует
18bpp (`COLMOD=0x66`, 3 байта/пиксель), да и часть регистров инициализации у него другая.

На реальном железе `RDID4` вернул мусор (`00 3B CB 00` — не 0/FF, похоже на наводку на
плавающем SDA-O), но **геометрия отрисовалась полностью корректно**: заливки R/G/B/белый
менялись без искажений, тест-паттерн ровный во всех 4 поворотах, финальный экран (полосы +
шахматка + серый блок со счётчиками) — всё как задумано по форме и расположению. (Отдельно
от этого была найдена и исправлена инверсия цветов — см. ниже; на геометрию/паттерн она не
влияла, поэтому вывод о совместимости с ST7796S по-прежнему в силе.) Если бы чип был
настоящим ILI9488, при 16bpp/чужой гамме картинка почти наверняка была бы битой —
раз она чистая, контроллер ST7796S-совместим. `RDID4` можно перепроверить (перепаять/
прозвонить SDA-O — PC11/SV4.2) при желании, но для работы это не требуется.

## Экран сетевого статуса

После смоук-теста (заливки + 4 поворота тест-паттерна) экран переключается на рабочий
вид: жёлтый заголовок, и строки `LINK / DHCP / IP / SERVER / TCP / UPTIME` (метка слева,
значение справа, шрифт 5x7 из `st7796s.c`), плюс мигающий раз в секунду квадратик-heartbeat.
`SERVER:` (адрес:порт, на который пытается коннектиться `tcp_echo_client`) статичен —
рисуется один раз при смоук-тесте, `main.c` форматирует его из `TCP_ECHO_SERVER_*`
(`tcp_echo_client.h`) и передаёт строкой в `TFT_App_SmokeTest()`, чтобы `Display/` по-прежнему
не подключал lwIP-заголовки напрямую. Остальные значения обновляет `TFT_App_AlivePoll()`,
вызывается из `main.c` там же, где уже считается `has_ip`/состояние TCP для UART-heartbeat —
никакого дублирования логики, просто те же переменные передаются ещё и на экран. Каждое
значение рисуется в поле фиксированной ширины (`STATUS_VALUE_CHARS`), так что более
короткое новое значение полностью перекрывает старое — не остаётся «хвостов» от
предыдущего текста.

**`LAST MSG:`** — последнее, что реально пришло от сервера по TCP, показывается жёлтым
на 2 секунды и само гаснет (`TFT_App_ShowReceived()`, вызывается из `main.c` сразу после
`tcp_echo_client_poll()`, только когда `tcp_echo_client_take_last_rx()` вернул что-то новое —
геттер в `tcp_echo_client.c`, независимый от вывода в UART). Таймер гашения проверяется
каждую итерацию цикла (а не раз в секунду, как остальные поля), чтобы строка исчезала
вовремя, а не с опозданием до 1 с. Многострочный ответ сервера показывается только первой
строкой (одно поле фиксированной ширины, не текстовый блок), а байты вне алфавита шрифта
(буквы/цифры/`. : - /`, без кириллицы) рисуются пустыми клетками — не мусором.

Список меток и позиций — в начале `tft_app.c` (`STATUS_Y_*`, `STATUS_LABEL_X`,
`STATUS_VALUE_X`). Добавить новую строку (например, для будущего сценария): завести
`STATUS_Y_XXX`, нарисовать метку в `status_draw_static()`, значение — новым вызовом
`status_draw_value()` в `TFT_App_AlivePoll()`.
