# Display — 3.5" ST7796S TFT (320×480), 4-wire SPI

Самодостаточный модуль: весь код и вся документация по дисплею лежат здесь, отдельно
от Ethernet/lwIP-части в `Core/`. Задуман так, чтобы дальнейшую доработку экрана
(новые виджеты, другие экраны) можно было вести, трогая только эту папку — `main.c`
знает только о четырёх функциях (см. «Слои кода» ниже).

## Структура

## Слои кода

```
main.c
  │  TFT_App_GPIO_Init()                        — сразу после MX_GPIO_Init(), до всего остального
  │  TFT_App_SPI3_Init()                       ─┐  один раз при старте, до MX_LWIP_Init() —
  │  TFT_App_SmokeTest()                       ─┘  блокирующие HAL_Delay() не должны стопорить DHCP/ETH
  │  TFT_App_AlivePoll(ip_str, link_up, ip_src, tcp)   — каждую итерацию while(1), сам ограничивает себя 1 Гц;
  │                                               main.c передаёт то же состояние netif/TCP, что уже
  │                                               считает для UART-heartbeat
  ▼
Display/Src/tft_app.c  (прикладной слой, PC10/11/12 + PA15/PC7/PD5/PD6)
```

и Ethernet-код, и `tft_app.c`.

## Подключение — коротко

9-контактный разъём SPI на плате-адаптере → плата f407, всего **2 разъёма** (SV4 + SV1) —
DC/RST/BL сгруппированы на SV1, чтобы не тянуть провода к третьему разъёму
(подробности и проверка перед включением — в [`docs/TFT_WIRING.md`](docs/TFT_WIRING.md)):

| Модуль (9-pin SPI) | STM32 | Разъём платы |
|---|---|---|
| GND | GND | SV4.6 |
| VCC | +5V (если на модуле есть LDO) / +3V3 | SV4.5 / SV2.1 |
| SCL | PC10 SPI3_SCK | SV4.3 |
| SDA | PC12 SPI3_MOSI | SV4.1 |
| SDA-O | PC11 SPI3_MISO | SV4.2 (нужен только для чтения ID) |
| CS | PA15 (GPIO) | SV4.4 |
| BL | PC7 (1 = вкл) | SV1.8 |
| RST | PD5 | SV1.9 |
| DC | PD6 | SV1.10 |
| BTN (кнопка страниц) | PC6, на GND | SV1.7 |

BL/RST/DC/BTN — четыре соседних пина SV1 (7/8/9/10), компактный жгут из четырёх проводов.
PC6/PC7/PD5/PD6 на этой плате подписаны как USART6/USART2 TX-RX (см. `hardware/BOARD.md`),
но ни один из этих UART в прошивке не занят — тот же случай, что и раньше с PB8 под BL. PC6
и PC7 сидят на порту GPIOC, который иначе в проекте не включается — `TFT_App_GPIO_Init()`
сам включает его тактирование. Кнопка — один вывод на PC6, второй на GND (например,
SV4.6); подтяжка к +3.3 В внутренняя, программная (`GPIO_PULLUP`), внешний резистор не
нужен.

**Перемычки IM0/IM1/IM2 на плате-адаптере** должны стоять в положении **SPI (4-wire)**
= `IM2=1, IM1=1, IM0=1`. **Проверено по фото `docs/tft_board_back.jpg`: на этом
экземпляре уже впаяны в `1/1/1`** — режим SPI, перепаивать не требуется. Таблица
режимов — в [`docs/TFT_3.5_board.md`](docs/TFT_3.5_board.md).

## Контроллер: ST7796S (подтверждено косвенно, RDID4 ненадёжен)

Плата-адаптер не подписана; по разводке 40-pin FPC она совпадает и с ST7796S, и с
ILI9488. Драйвер (`st7796s.c`) целиком написан под ST7796S — командный набор
разблокировки (`0xF0/0xC3/0x96`), таблицы гаммы (`0xE0/0xE1`), `COLMOD=0x55`
(16 бит/пиксель). Для настоящего ILI9488 по SPI это, как правило, **не сработает
корректно** — тот обычно не принимает 16bpp по последовательному интерфейсу и требует
18bpp (`COLMOD=0x66`, 3 байта/пиксель), да и часть регистров инициализации у него другая.

На реальном железе `RDID4` вернул мусор (`00 3B CB 00` — не 0/FF, похоже на наводку на
плавающем SDA-O), но **геометрия отрисовалась полностью корректно**: заливки R/G/B/белый
менялись без искажений, тест-паттерн ровный во всех 4 поворотах, финальный экран (полосы +
шахматка + серый блок со счётчиками) — всё как задумано по форме и расположению. (Отдельно
от этого была найдена и исправлена инверсия цветов — см. ниже; на геометрию/паттерн она не
влияла, поэтому вывод о совместимости с ST7796S по-прежнему в силе.) Если бы чип был
настоящим ILI9488, при 16bpp/чужой гамме картинка почти наверняка была бы битой —
раз она чистая, контроллер ST7796S-совместим. `RDID4` можно перепроверить (перепаять/
прозвонить SDA-O — PC11/SV4.2) при желании, но для работы это не требуется.

## Многостраничный экран статуса

После смоук-теста (заливки + 4 поворота тест-паттерна) экран переключается на рабочий,
многостраничный режим. Кнопка на **SV1.7/PC6** (на GND, внутренняя подтяжка) листает
страницы по кругу; текущая страница видна в правом верхнем углу как `n/N`. Каждая
страница — свой заголовок (жёлтым) + `n/N`; heartbeat-квадратик внизу слева мигает
раз в секунду **на любой странице** — по нему видно, что прошивка жива, даже если вы
сейчас смотрите не на ту страницу, где что-то могло зависнуть.

| # | Страница | Что показывает |
|---|---|---|
| 1/4 | **SETUP** | `LINK / DHCP / IP / SERVER / TCP / UPTIME / FRAME / CHIP ID / NAME` |
| 2/4 | **RECEIVED** | Последнее сообщение от TCP-сервера целиком, многострочно |
| 3/4 | **REMOTE** | Приборы с данными от сервера: 2 стрелочных, 3 цифровых, 2 ползунка, 4 лампы — модуль [`Panel/`](../Panel/README.md) |
| 4/4 | **LOCAL** | Локальные приборы и органы управления: 3 столбика, стрелочный, цифровой, 4 кнопки, ползунок — [`Panel/`](../Panel/README.md) |

Пока реальных данных нет, REMOTE/LOCAL показывают **демо-анимацию** (внизу `SERVER: DEMO` /
`LOCAL: DEMO`). Добавить ещё страницу: завести `TFT_PAGE_XXX` в `enum TFT_Page` (перед `TFT_PAGE_COUNT`,
он посчитается сам), написать `draw_page_xxx_static(void)`, добавить `case` в
`draw_page_static()`; если странице нужны поля, обновляющиеся раз в секунду — добавить
`if (s_page == TFT_PAGE_XXX) { ... }` в `TFT_App_AlivePoll()` рядом с уже существующим
блоком для SETUP.

### Кнопка переключения страниц

PC6 (SV1.7), активный уровень низкий, подтяжка к +3.3 В — внутренняя программная
(`GPIO_PULLUP` в `TFT_App_GPIO_Init()`), внешний резистор не нужен: один вывод кнопки на
PC6, второй на GND. Антидребезг — по времени (`BTN_DEBOUNCE_MS` = 50 мс: изменение
состояния принимается не чаще этого интервала), проверяется **каждую итерацию** главного
цикла (а не раз в секунду) — переключение страницы происходит мгновенно по нажатию, без
задержки до 1 с.

### Страница SETUP

`LINK/DHCP/IP/SERVER/TCP/UPTIME/FRAME/CHIP ID/NAME`, метка слева/значение справа, шрифт
5x7. `SERVER:`/`FRAME:`/`CHIP ID:`/`NAME:` статичны — рисуются один раз при возврате на
страницу. `SERVER:` и `NAME:` теперь приходят из `Config/Inc/device_config.h` (постоянные
настройки, см. `Config/README.md`) — `main.c` читает их через `device_config_get()` и
передаёт строками в `TFT_App_SmokeTest()`, чтобы `Display/` по-прежнему не подключал ни
lwIP-, ни Config-заголовки напрямую. После сохранения новых настроек (веб-страница или
TCP-конфигуратор) `main.c` замечает смену `device_config_revision()` и вызывает
`TFT_App_UpdateInfo()` — `SERVER:`/`NAME:` обновляются на экране сразу, без перезагрузки
(если SETUP сейчас не на экране — при следующем возврате на неё). Остальные поля обновляет `TFT_App_AlivePoll()` раз
в секунду, **только пока активна эта страница** — вызывается из `main.c` там же, где уже
считается `has_ip`/состояние TCP для UART-heartbeat, никакого дублирования логики.
Каждое значение рисуется в поле фиксированной ширины (`STATUS_VALUE_CHARS`), так что
более короткое новое значение полностью перекрывает старое.

**`NAME:`** — имя/метка устройства, настраивается по сети без пересборки прошивки: через
веб-страницу `http://<IP модуля>/` или TCP-конфигуратор (`SET NAME ...`), см.
`Config/README.md`.

**`CHIP ID:`** — **CRC32** от уникального 96-битного заводского номера чипа (STM32F4:
OTP-регистр по фиксированному адресу `0x1FFF7A10`, см. RM0090 §39.1 «Unique device ID
register», `stm32_uid_word()`/`stm32_uid_crc32()` в `tft_app.c` — обычное чтение памяти,
без периферии/инициализации). Статичен, как `SERVER:`/`FRAME:` — заводской номер не
меняется в рантайме.

Показывается именно CRC32 (8 hex-символов, влезает в одну строку), а не все 24 символа
сырого ID: во-первых, не влезает в 16-символьное поле значения (пришлось бы разбивать на
2 строки); во-вторых, часть 96 бит (поле `LOT_NUM` — номер производственной партии) у ST
часто кодируется как читаемый десятичный/ASCII-подобный текст, а не как случайные биты
(отсюда и вопрос — на экране был подозрительно «ровный» номер без единой буквы A-F), так
что CRC32 заодно превращает его в равномерно распределённое короткое значение, удобное
как компактный идентификатор платы. Использован стандартный отражённый CRC-32 (полином
`0xEDB88320`, тот же алгоритм, что `zlib.crc32()`/`binascii.crc32()` в Python/`cksum`) —
можно независимо перепроверить по 24-значному сырому ID, который печатается в лог USART1
при старте вместе с CRC32: `[tft] chip UID = <24 hex> (CRC32 <8 hex>)`.

Для идентификации платы на сервере используйте именно этот CRC32 (или сырой 96-битный
ID из лога), а не MAC-адрес: он сейчас жёстко прошит одинаковым для всех плат с этой
прошивкой (`ETH_MAC_ADDR0..5` в `Core/Inc/stm32f4xx_hal_conf.h`, сейчас
`02:00:00:00:00:01`) — при нескольких платах в одной сети будет MAC-коллизия, если не
поменять байт вручную под каждую плату. IMEI не применим — на плате нет сотового модема.

### Страница RECEIVED

Последнее, что реально пришло от сервера по TCP — **целиком**, а не только первая строка:
разбивка по переносам строк сервера (CR/LF), каждая строка при необходимости ещё и
заворачивается по ширине экрана (`STATUS_RX_CHARS` символов) — до `STATUS_RX_MAX_ROWS`
(сейчас 18) строк; всё, что не поместилось, отбрасывается. Текст **не гаснет сам** (в
отличие от прежней версии на общем экране) — держится, пока не придёт новое сообщение;
страница целиком отдана этому, автогашение через 2 с больше не нужно. Если новое
сообщение короче предыдущего — лишние строки снизу гасятся отдельно (`s_rx_rows_used`),
не остаётся «хвостов». Байты вне алфавита шрифта (буквы/цифры/`. : - / ! #`, без
кириллицы) рисуются пустыми клетками — не мусором.

Сообщение хранится в `s_last_msg` (сырой текст, ещё не завёрнутый), поэтому переключение
на эту страницу всегда показывает последнее пришедшее, даже если оно прилетело, пока была
открыта другая страница (`TFT_App_ShowReceived()` перерисовывает страницу немедленно,
только если она активна; иначе просто запоминает — отрисовка произойдёт при следующем
переключении сюда). Буфер под приём: `LAST_RX_SNAPSHOT_SIZE` в `tcp_echo_client.c` (220
байт) и `rx_snapshot` в `main.c` (тот же размер) — сообщение с кириллицей в UTF-8
(2 байта/символ) уже занимает ~100 байт, оставлен запас.

Список меток и позиций для всех страниц — в начале `tft_app.c` (`STATUS_Y_*`,
`STATUS_LABEL_X`, `STATUS_VALUE_X`).
