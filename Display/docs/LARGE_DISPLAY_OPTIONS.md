# Большой дисплей: что возможно на этой плате (заметка, 2026-09-24)

Теоретический разбор, ничего не заказано и не реализовано. Сейчас стоит ST7796S 3,5"
320×480 по SPI3 (разъём SV4) — см. [`TFT_WIRING.md`](TFT_WIRING.md).

## Итог

- **Практический максимум — 10,1" 1024×600 / 1280×800**, но только «умный» дисплей
  со своим графическим контроллером и видеопамятью (RA8876/RA8889, EVE BT817/818,
  UART-HMI DWIN/Nextion).
- Дисплей того же типа, что сейчас (STM32 шлёт каждый пиксель), — около **4", 320×480**.
- **1920×1080 напрямую — невозможно.** Только через отдельный компьютер с браузером
  (Raspberry Pi и т.п.), который показывает страницу модуля.

## Ограничения STM32F407 и платы

| Что | Значение | Следствие |
|---|---|---|
| Видеовыход (LTDC, HDMI, LVDS, MIPI-DSI) | нет (LTDC есть только у F429/F469/F7/H7) | RGB/HDMI-панель не подключить |
| ОЗУ | 192 КБ всего, свободно ~60 КБ | буфер кадра в STM32 не поместится (1080p×16 бит ≈ 4,1 МБ); картинка должна храниться в памяти дисплея |
| Шина к дисплею | только SPI3 на SV4, ~20 МГц макс., реально ~1,2 МБ/с | полный кадр 320×480 = 246 мс (замер); 1080p был бы ~3,5 с на кадр |
| Параллельная шина (FSMC/8080) | на плате нет свободных 13+ выводов | только SPI (или UART) |

## Варианты по нарастанию размера

| Тип | Пример | Размер / разрешение | Как рисует | Скорость |
|---|---|---|---|---|
| Простой SPI (как сейчас) | ST7796S, ILI9488 | 3,5–4", 320×480 | STM32 считает все пиксели | полный кадр ~0,25 с |
| SPI + графический контроллер | RA8875 | 5–7", 800×480 | текст, прямоугольники по командам | мгновенно для простой графики |
| SPI + контроллер с SDRAM | RA8876 / RA8889 | 7–10,1", 1024×600 | то же + хранит картинки | аналогично |
| SPI + EVE | Bridgetek BT817/818 (модули Riverdi) | до 10,1", 1280×800 | графика, шрифты, виджеты, сенсор | плавно, 60 кадров/с |
| UART-панель (HMI) | DWIN DGUS, Nextion | до 10,1", 1024×600 / 1280×800 | экраны рисуются в их редакторе, STM32 шлёт только значения | мгновенно |

Разрешения — по общим сведениям; перед покупкой проверить в даташите конкретного
модуля, что он поддерживает **SPI** (или UART для HMI), а не только RGB/LVDS.

## Что учесть

- **Подключение:** все варианты — к SV4 (SPI + 2–3 управляющих вывода: CS, INT/RST).
  UART-панели нужен свободный UART: USART3 в прошивке инициализирован, но проверить,
  выведен ли он на разъём.
- **Код:** драйвер ST7796S не подходит, для каждого контроллера нужен свой. Меньше всего
  кода — UART-HMI; самая красивая графика — EVE.
- **Питание:** подсветка 7–10" ≈ 0,5–2 А, нужен отдельный источник 5/12 В.
- **Рекомендация для 10":** EVE BT817/818 (1280×800, сенсор) — если важна графика;
  DWIN 10,1" — если нужно меньше кода.

## 1920×1080 через Raspberry Pi

- Модуль уже имеет веб-сервер (порт 80) — добавить страницу `/status` с данными экрана.
- Raspberry Pi (или любой ПК/планшет/Smart TV) с HDMI-монитором 1920×1080 открывает её в
  браузере в режиме киоска (Chromium на весь экран при загрузке). Плату менять не нужно.
- Pi 4/5 — комфортно; Pi 3 (1 ГБ) — справится со страницей статуса, тяжёлые страницы медленно.
  ОС — Raspberry Pi OS 64-bit (Bookworm).
- Разработка для Pi из этой же среды: VS Code + расширение **Remote - SSH** (код, терминал,
  отладка на Pi), либо Claude Code по `ssh`/`scp` из Windows (OpenSSH встроен), либо
  Claude Code на самой Pi (Pi 4/5). Языки: Python (есть в ОС), C/C++ (`gcc` на Pi), Node/Go/Rust.
- Подготовка: Raspberry Pi Imager → включить SSH, пользователь/пароль, Wi-Fi; Pi в ту же
  сеть 10.0.1.x, IP — из роутера.
