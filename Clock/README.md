# Clock — сетевые часы (NTP)

Время суток по NTP и отдельная страница **CLOCK** на дисплее (кнопка страниц, после LOCAL).

## Файлы

| Файл | Что делает |
|---|---|
| `Inc/clock_config.h` | Настройки: NTP-сервер, часовой пояс, летнее время, интервалы |
| `Inc/clock.h`, `Src/clock.c` | SNTP-клиент на raw UDP lwIP + отсчёт времени + местное время |
| `Inc/clock_page.h`, `Src/clock_page.c` | Страница CLOCK на TFT |

## Как работает

- `clock_poll(has_ip)` в главном цикле (`main.c`). Как только есть IP — запрос к
  `CLOCK_NTP_SERVER` (по умолчанию `pool.ntp.org`, через DNS). DNS-сервер выдаёт DHCP;
  при статическом IP используется шлюз.
- Ответ сервера (с поправкой на половину времени прохождения) становится базой, дальше
  время считается от системного тика (кварц HSE). Пересинхронизация — раз в час; при
  неудаче — повтор через 10 с (пока время ни разу не получено) или через 60 с.
- Местное время: `CLOCK_TZ_OFFSET_MIN` (Эстония: +120 мин) и, если `CLOCK_EU_DST = 1`,
  +1 час с последнего воскресенья марта 01:00 UTC до последнего воскресенья октября.
- RTC микроконтроллера не используется: после перезагрузки время снова берётся из сети
  (первая синхронизация — через секунды после получения IP).
- В UART: `[clock] synced 24.09.2026 14:03:22 local (адрес сервера, rtt N ms)`, а также
  сообщения о неудачах DNS / NTP.

## Страница CLOCK

```
 CLOCK                  5/6
   14 : 03 : 22          ← 7-сегментные цифры, 24 ч
    24.09.2026
     THURSDAY
 TZ:   UTC+3 SUMMER
 SYNC: OK AT 14:03:22
 NTP:  pool.ntp.org
```

Ничего не перерисовывается по таймеру: каждый элемент сравнивается с тем, что уже на
экране, и рисуется заново только при изменении. Обычно раз в секунду меняется только
цифра секунд; минуты, часы, дата и день недели — в момент смены; строки TZ/SYNC — при
синхронизации или переходе на летнее/зимнее время. До первой синхронизации цифры пустые,
дата `--.--.----`, в SYNC — `WAITING`.

День недели — по-английски: шрифт дисплея латинский.
