# Diag — диагностика и тестовые функции

Всё, что нужно только для отладки и проверки, живёт здесь и выключается одним
переключателем. Рабочий код (`Core/`, `Display/`, `Panel/`, `Config/`) о диагностике
знает только через вызовы-«крючки», которые при выключенной функции превращаются в
пустые inline-заглушки и в прошивку не попадают.

## Переключатели — `Inc/diag_config.h`

| Define | По умолчанию | Что делает |
|---|---|---|
| `DIAG_ENABLE` | 1 | Общий выключатель: `0` убирает всё из `Diag/` |
| `DIAG_CPU_STATS` | 1 | Замер загрузки главного цикла (счётчик тактов DWT) |
| `DIAG_CPU_UART` | 1 | Сводка в USART1 каждые `DIAG_CPU_UART_PERIOD_S` секунд |
| `DIAG_CPU_UART_PERIOD_S` | 5 | Период сводки в UART |
| `DIAG_CPU_PAGE` | 1 | Страница CPU на дисплее (в цикле кнопки страниц) |
| `DIAG_CAN_LOOPBACK` | 1 | Самопроверка CAN1 во внутренней петле (см. ниже). **Пока включена, реальная шина на J3 не используется** |
| `DIAG_CAN_REPORT_S` | 5 | Период отчёта самопроверки CAN в UART |

`DIAG_CPU_UART` и `DIAG_CPU_PAGE` без `DIAG_CPU_STATS` не работают и выключаются вместе
с ним. Любое значение можно задать и из командной строки компилятора (`-DDIAG_ENABLE=0`).

Цена в прошивке: ~2,3 КБ Flash и ~200 Б RAM при всём включённом.

## Загрузка процессора (`diag_cpu`)

RTOS нет, главный цикл крутится постоянно — «простоя» в привычном смысле нет. Поэтому
меряется, **куда уходит время цикла**. `main.c` обрамляет каждую работу вызовами
`diag_cpu_begin()/diag_cpu_end()`:

| Секция | Что внутри |
|---|---|
| ETH | `ethernetif_input()` + `ethernetif_poll_link()` |
| LWIP | `sys_check_timeouts()` |
| TCP | `tcp_echo_client_poll()` |
| HTTP | `config_http_poll()` |
| TFT | `TFT_App_AlivePoll()` (включая панель и смену страниц) + `TFT_App_ShowReceived()` |
| OTHER | всё остальное: мигание LED, логика DHCP/watchdog, сам цикл |

Прерывания засчитываются той секции, которую прервали.

Показатели за окно 1 с:
- **LOOPS/S** — проходов цикла в секунду; чем больше, тем свободнее процессор.
- **LOOPMAX** — самый долгий проход цикла = худшая задержка, с которой будет
  обработан пришедший Ethernet-кадр. Главный показатель для системы на опросе.
- **% и MAX по секциям** — доля времени и самый долгий одиночный вызов.

В UART (за 5 с, MAX — худший за период):
```
[cpu] 48213 loops/s, max pass 612MS | ETH 1.2% (max 310US) LWIP 0.4% (max 45US) ... OTHER 60.1%
```
Время самой печати (~1–2 мс) из статистики исключено.

## Самопроверка CAN (`diag_can`)

Драйвер `CAN/` переводится в режим «тихая петля» (bxCAN LBKM + SILM): отправленный кадр
возвращается в собственный приёмник внутри микросхемы, на ножки ничего не выходит.
Раз в секунду отправляется кадр с номером — по очереди со стандартным (0x7E1) и
расширенным (0x18DAF1E1) ID, 8 байт — и проверяется, что он вернулся тем же (ID, длина,
данные) не позже чем через 100 мс. Каждые 5 с в UART:

```
[can] CAN1 up: 500 kbit/s (APB1 40 MHz, presc 5, 16 tq), SILENT LOOPBACK self-test - real bus not used
[can] rx 7E1 [8] 00 00 00 02 CA FE 55 AA
[can] rx 18DAF1E1 [8] 00 00 00 03 CA FE 55 AA
[diag-can] loopback PASS: sent 5 ok 5 lost 0 bad 0 (total ok 25 fail 0)
```

Проверяются драйвер, тайминги, фильтр, прерывание, очередь. **Не** проверяются трансивер
TCAN1044V, разъём J3 и проводка — для этого нужен второй узел (USB-CAN адаптер или второй
модуль) и `DIAG_CAN_LOOPBACK 0`.

## Добавить новую диагностическую функцию

1. Код — в `Diag/Src/`, заголовок — в `Diag/Inc/`, файл — в `PROJECT_SOURCES` в `CMakeLists.txt`.
2. Переключатель `DIAG_<ИМЯ>` — в `diag_config.h`, в блоке зависимостей привязать к `DIAG_ENABLE`.
3. В заголовке — заглушки `static inline` для выключенного случая, чтобы вызовы в
   рабочем коде не требовали `#if`.
