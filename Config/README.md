# Config — persistent settings + network configurator

Самодостаточный модуль: постоянные настройки устройства и способ их менять по сети,
не трогая прошивку/`Core/`. Появился взамен жёстко прошитых в `tcp_echo_client.h`
констант (`TCP_ECHO_SERVER_IP0..3`/`PORT`) — раньше смена адреса сервера требовала
пересборки и перепрошивки; теперь это делается из браузера (или одной TCP-командой) с
любого компьютера/телефона в той же сети, без кабеля и без Claude Code.

## Веб-страница настройки (основной способ)

Откройте в браузере **`http://<IP модуля>/`** (IP виден на экране, страница SETUP,
строка `IP:`). Форма уже заполнена текущими значениями:

| Поле | Применяется |
|---|---|
| Имя устройства | сразу (строка `NAME:` на экране обновляется без перезагрузки) |
| IP / порт TCP-сервера | сразу: клиент переподключается к новому адресу, `SERVER:` на экране обновляется |
| Режим IP (DHCP / Статический), статический IP, маска, шлюз | после перезагрузки — кнопка **«Перезагрузить»** на той же странице |

**«Сохранить»** сначала проверяет *все* поля; при любой ошибке (неверный IP, порт вне
1–65535, пустое имя, в статическом режиме — нулевой IP/маска) ничего не меняется, и
форма возвращается с красной подсказкой. При успехе — зелёная плашка «Сохранено и
применено» (или «…вступят в силу после перезагрузки», если менялся режим/адрес IP), и
настройки уже записаны во Flash.

**«Перезагрузить»** показывает страницу «Перезагрузка…», через 0,5 с перезапускает
модуль, и через ~12 с страница сама открывается заново. Если IP-адрес менялся —
откройте новый адрес вручную.

Реализация: `Src/config_http.c` — минимальный HTTP/1.0-сервер на raw API lwIP, форма
методом GET (все параметры в строке запроса, тела запроса нет), один запрос на
соединение (`Connection: close`). Кириллица на странице — UTF-8; в поле имени лучше
латиница/цифры, экран модуля кириллицу не отображает.

## Структура

| Путь | Что это |
|---|---|
| `Inc/device_config.h`, `Src/device_config.c` | Хранилище настроек: структура `DeviceConfig`, чтение/запись во Flash (последний сектор, `0x080E0000`, сектор 11 — далеко от прошивки, сейчас занимающей ~17% из 1 МБ), проверка CRC32, откат на дефолты при первом старте/повреждении. Не знает ни о lwIP, ни о протоколе, который её пишет. |
| `Inc/config_http.h`, `Src/config_http.c` | Веб-страница настройки на порту 80 (см. выше). Знает про lwIP и `device_config.h`, но не про `Display/`/`tcp_echo_client` — о сохранении остальные узнают через `device_config_revision()`. |
| `Inc/config_server.h`, `Src/config_server.c` | TCP-слушатель на порту 7000, построчный текстовый протокол (см. ниже). Знает про lwIP (raw API, как `tcp_echo_client.c`, только в роли сервера, а не клиента) и про `device_config.h`, но не про `Display/`. |

## Слои и кто чем пользуется

```
main.c
  │  device_config_load()     — сразу после boot-сообщения, до всего остального
  │                              (нужен и экрану, и MX_LWIP_Init())
  │  MX_LWIP_Init()            — читает use_static_ip: static IP или DHCP
  │  config_server_init()      — после MX_LWIP_Init(), чисто событийный (accept/recv),
  │                              отдельного poll() в цикле не нужно
  │  config_http_init()        — то же для порта 80; config_http_poll() в цикле нужен
  │                              только для отложенной перезагрузки после /reboot
  │  цикл: device_config_revision() изменилась → TFT_App_UpdateInfo() (SERVER:/NAME:),
  │        а если сменился адрес сервера → tcp_echo_client_restart()
  ▼
Config/Src/device_config.c  (постоянное хранилище)
      ▲
      │ device_config_get()
      │
Core/Src/tcp_echo_client.c   — читает server_ip/server_port заново при каждой
                                попытке (пере)подключения, без кэширования
Display/Src/tft_app.c        — SERVER:/NAME: на странице SETUP: при загрузке из
                                `TFT_App_SmokeTest()`, после сохранения — `TFT_App_UpdateInfo()`
```

## TCP-конфигуратор (порт 7000, построчно, `\r\n`) — запасной способ

Подключиться можно чем угодно — `nc <IP модуля> 7000`, PuTTY (Connection type: **Raw**,
Host = IP модуля, Port = 7000), или (если ни того, ни другого нет под рукой)
[`scripts/config-client.ps1`](../scripts/config-client.ps1) — интерактивный клиент на
чистом PowerShell без сторонних утилит:
```
powershell -ExecutionPolicy Bypass -File scripts/config-client.ps1 <IP модуля>
```
IP модуля виден на экране (страница SETUP, `IP:`).

| Команда | Действие |
|---|---|
| `SET SERVER <ip> <port>` | Адрес `tcp_echo_client`. Применяется сразу же на следующей попытке (пере)подключения — перезагрузка не нужна. |
| `SET NAME <текст>` | Имя устройства (до 23 символов, обрезается длиннее — безопасно). |
| `SET IP DHCP` | Переключить на DHCP. Требует `SAVE` + `REBOOT`. |
| `SET IP STATIC <ip> <netmask> <gateway>` | Переключить на статический IP. Требует `SAVE` + `REBOOT`. |
| `SAVE` | Записать текущие настройки во Flash (иначе всё слетит при следующей перезагрузке). |
| `REBOOT` | `NVIC_SystemReset()` — нужен, чтобы применились изменения режима IP (SERVER/NAME применяются и без этого). |
| `GET` | Дамп текущих настроек (то, что реально в ОЗУ, не обязательно то, что уже сохранено). |

Пример сессии (проверено вживую):
```
$ nc 10.0.1.140 7000
READY (SET SERVER/NAME/IP, SAVE, REBOOT, GET)
SET NAME room-3
OK (SAVE to persist)
SAVE
OK
GET
NAME=room-3
SERVER=10.0.1.16:5000
IPMODE=DHCP
STATIC_IP=0.0.0.0
STATIC_MASK=0.0.0.0
STATIC_GW=0.0.0.0
OK
```

Одновременно поддерживается только **одна** сессия — вторая попытка подключения
получает `ERR busy, one config session at a time` и закрывается сразу (проще и
безопаснее, чем делить один буфер строки между несколькими клиентами; это
административный интерфейс для одного техника, не сервис с параллельными
пользователями).

## Хранение

`DeviceConfig` (magic + версия + CRC32 + сами поля) пишется в последний сектор Flash
(сектор 11, `0x080E0000`, 128 КБ) — специально максимально далеко от прошивки (сейчас
~176 КБ из 1 МБ), чтобы рост прошивки не грозил однажды дотянуться до этого сектора.
`device_config_load()` при старте проверяет magic/версию/CRC32 — если что-то не сошлось
(чистый Flash при самой первой прошивке, битый CRC, будущий бамп версии без миграции),
тихо откатывается на дефолты (тот же адрес сервера, что был захардкожен раньше:
`10.0.1.16:5000`).

`device_config_save()` — блокирующая операция (стирание сектора занимает ~1 с, всё это
время CPU не может выполнять код из Flash вообще, то есть весь Ethernet-стек тоже
стоит). Это редкая, инициированная оператором операция (по команде `SAVE` / кнопке
«Сохранить»), не на периодическом пути — тот же компромисс, что уже принят для
~7-секундного блокирующего теста дисплея при загрузке.

## Найденная и исправленная ошибка: зависание в `tcp_input()` после сброса ETH

Симптом: после нескольких запросов к веб-странице модуль переставал отвечать совсем
(ни ping, ни HTTP), хотя CPU работал — остановка через OpenOCD показала бесконечный
цикл в `tcp_input()` по списку `tcp_tw_pcbs`: два соединения порта 80 в TIME_WAIT
ссылались друг на друга (кольцо).

Причина — в `ethernetif_reset()` (`Core/Src/ethernetif.c`, аварийный сброс ETH после
3 неудачных подключений клиента и т.п.): `memp_init()` объявлял весь пул TCP PCB
свободным, хотя PCB всё ещё числились в списках lwIP. Следующее соединение получало
такой «свободный» PCB, lwIP регистрировал его повторно — и список замыкался. Раньше это
не проявлялось, потому что соединения в TIME_WAIT оставляет только сервер, который
закрывает первым, — а первым таким сервером стал HTTP.

Исправление: перед очисткой пулов все активные/TIME_WAIT/bound PCB корректно
закрываются через `tcp_abort()` (их владельцы получают обычный `err`-callback), а пул
слушающих PCB (порты 7000 и 80) не очищается — оба конфигуратора переживают сброс ETH.
Заодно `ethernetif_reset()` и восстановление линка больше не включают DHCP в режиме
статического IP (`ethernetif_set_use_dhcp()`, выставляется в `MX_LWIP_Init()`).
Проверено: клиент направлен на закрытый порт → серия сбросов ETH под постоянной
HTTP-нагрузкой (200 запросов за 2 мин) → модуль каждый раз восстанавливался.

## Проверено вживую
- Веб-страница: форма с текущими значениями; сохранение имени/сервера («Сохранено и
  применено», `NAME:`/`SERVER:` на экране обновились); ошибки — неверный IP сервера,
  порт 99999, статический режим с IP/маской 0.0.0.0 (ничего не сохраняется); 5
  сохранений подряд + 30 GET подряд; `/favicon.ico` → 404; смена порта сервера →
  клиент переподключился к новому адресу.
- `GET` сразу после прошивки — дефолты корректны.
- `SET NAME` → `SAVE` → `REBOOT` → переподключение → `GET` — новое имя пережило полную
  перезагрузку.
- Статический IP (`SET IP STATIC`) собран и реализован в `MX_LWIP_Init()`, но пока не
  проверен на реальном железе — сделайте `SET IP STATIC ... `, `SAVE`, `REBOOT` и
  сверьте `IP:` на экране/`GET` после перезагрузки.
