# CAN — драйвер CAN1

## Железо

| Что | Где |
|---|---|
| Контроллер | bxCAN **CAN1**, PA11 = RX, PA12 = TX (AF9) |
| Трансивер | U3 **TCAN1044V**, STB → R1 10k на GND (всегда активен), VIO = 3V3, VCC = +5V |
| Разъём | **J3** (4 pin): 1 GND, 2 CANL, 3 CANH, 4 +5V |
| Терминатор | R2/R30 2×49.9 Ом (split, 120 Ом) — впаян постоянно: модуль должен стоять **на конце шины** |
| Защита | D4 PESD1CAN |

Подробнее — `hardware/BOARD.md`.

## Файлы

| Файл | Что делает |
|---|---|
| `Inc/can_config.h` | Скорость, режим «только слушать», лог, размер очереди |
| `Inc/can_bus.h`, `Src/can_bus.c` | Драйвер на регистрах bxCAN (HAL CAN в проекте нет) |

## Настройки (`can_config.h`)

| Define | По умолчанию | Что делает |
|---|---|---|
| `CAN_BITRATE_KBPS` | 500 | Скорость; делитель считается от реальной частоты APB1 (40 МГц), точка выборки ~87,5 % |
| `CAN_SILENT` | 0 | 1 = только слушать: модуль не шлёт ACK и ошибки, не передаёт — безопасно для чужой шины |
| `CAN_LOG_MAX_PER_S` | 20 | Сколько принятых кадров в секунду печатать в UART (печать блокирующая) |
| `CAN_STATS_PERIOD_S` | 10 | Сводка раз в N секунд (только если что-то было) |
| `CAN_RX_QUEUE_LEN` | 32 | Очередь между прерыванием и главным циклом |

## Как работает

- `can_bus_init()` при старте: тактирование, ножки, тайминги, фильтр «принимать всё»
  (стандартные и расширенные кадры) в FIFO0, прерывание приёма.
- Прерывание `CAN1_RX0` перекладывает кадры из аппаратного FIFO (3 кадра) в очередь.
- `can_bus_poll()` в главном цикле: печатает кадры в UART, отдаёт каждый в обработчик
  приложения (`can_bus_set_rx_handler()`), сообщает о смене состояния шины.
- `can_bus_send()` кладёт кадр в свободный аппаратный почтовый ящик (их 3) и сразу
  возвращается. **Сейчас прошивка сама ничего не передаёт** — функция есть, вызова нет.
- Bus-off восстанавливается аппаратно (ABOM); автоматический повтор передачи включён.

## Что видно в UART

```
[can] CAN1 up: 500 kbit/s (APB1 40 MHz, presc 5, 16 tq), normal mode
[can] state OFF -> ACTIVE (tec 0 rec 0)
[can] rx 123 [8] 11 22 33 44 55 66 77 88
[can] rx 18FF0102 [4] 01 00 FF 7F        ← расширенный (29-bit) ID
[can] ... 340 more frames not logged      ← если больше CAN_LOG_MAX_PER_S в секунду
[can] 10 s: rx 3520 tx 0 lost 0 | total rx 3520, ACTIVE tec 0 rec 0
```

`lost` — кадры, потерянные из-за переполнения FIFO или очереди.
Если при старте `did not leave init mode` — линия RX держится в доминанте: проверьте
питание +5V трансивера и проводку J3.

## Пример передачи

```c
CanFrame f = { .id = 0x123, .ext = 0, .rtr = 0, .len = 2, .data = { 0xAB, 0xCD } };
if (!can_bus_send(&f)) { /* все 3 ящика заняты или режим CAN_SILENT */ }
```

Без второго узла на шине кадр не получит ACK, контроллер будет повторять его, счётчик
ошибок TEC вырастет, и шина уйдёт в ERROR-PASSIVE — это нормально для одиночного узла.
