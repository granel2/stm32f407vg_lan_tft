# Panel — страницы приборов на TFT

Дополнение к экрану [`Display/`](../Display/README.md): две страницы с кнопками, лампами,
цифровыми и стрелочными приборами, ползунками и столбиками. Листаются той же кнопкой
(PC6), что и SETUP / RECEIVED: **SETUP → RECEIVED → REMOTE → LOCAL**.

Сейчас это **примеры изображения**: раскладка и типы приборов — образец, значения
анимирует встроенное демо. Что именно показывать и откуда брать данные — решается дальше
(формат данных от сервера, локальные входы, органы управления — см. «Что решить»).

## Страницы

**REMOTE** — значения, приходящие с удалённого сервера:

```
┌──────────────────────────────────────┐
│ REMOTE                          3/4  │
│ ┌─PRESSURE─────┐ ┌─SPEED────────┐    │   2 стрелочных прибора
│ │   ╭──────╮   │ │   ╭──────╮   │    │   (шкала 240°, зоны норма/внимание/авария)
│ │  ╱   ╲    ╲  │ │  ╱    ╱   ╲  │    │
│ │    5.3 BAR   │ │   1500 RPM   │    │
│ └──────────────┘ └──────────────┘    │
│ [TEMP  C][FLOW L/M][VOLT   V]        │   3 цифровых индикатора
│ [VALVE 1 ════●──────     35 %]       │   2 ползунка
│ [VALVE 2 ══════════●──   80 %]       │
│ (●)PUMP  (●)FAN  (○)HEAT  (○)ALARM   │   4 лампы
│ ■  SERVER: DEMO                      │   ■ = heartbeat (tft_app.c)
└──────────────────────────────────────┘
```

**LOCAL** — собственные входы модуля и органы управления:

```
┌──────────────────────────────────────┐
│ LOCAL                           4/4  │
│ ┌AIN1┐┌AIN2┐┌AIN3┐ ┌─SUPPLY───────┐  │   3 столбика + стрелочный
│ │ ▓▓ ││    ││ ▓▓ │ │   ╭──────╮   │  │
│ │ ▓▓ ││ ▓▓ ││ ▓▓ │ │    24.0 V    │  │
│ │1.8V││0.9V││2.5V│ ├─UPTIME──── S─┤  │   цифровой (реальный аптайм)
│ └────┘└────┘└────┘ │      1234    │  │
│ [ RELAY 1 ] [ RELAY 2 ]              │   4 кнопки (залиты = включены)
│ [  START  ] [  STOP   ]              │
│ [SETPOINT ═══════●────   62.5 %]     │   ползунок уставки
│ ■  LOCAL: DEMO                       │
└──────────────────────────────────────┘
```

## Каналы

Каждый прибор показывает один **канал** (0…31). Значение канала — целое число в
**десятых** (`237` = 23,7). Карта каналов — в шапке [`Src/panel_pages.c`](Src/panel_pages.c):

| Страница | Каналы |
|---|---|
| REMOTE | 0 PRESSURE bar, 1 SPEED rpm, 2 TEMP °C, 3 FLOW л/мин, 4 VOLT В, 5–6 VALVE 1/2 %, 7–10 лампы PUMP/FAN/HEAT/ALARM (0/1) |
| LOCAL | 16–18 AIN1–3 В, 19 SUPPLY В, 20 UPTIME с (**реальный**), 21–24 кнопки RELAY 1/2, START, STOP (0/1), 25 SETPOINT % |

Реальные данные подаются одним вызовом:
```c
Panel_SetChannel(0, 53);   /* PRESSURE = 5.3 bar */
```
После первого такого вызова демо перестаёт трогать этот канал (остальные продолжают
анимироваться). Демо целиком выключается `#define PANEL_DEMO 0` (в `panel.h` или
`-DPANEL_DEMO=0` в CMake).

## Как добавить / изменить прибор

Страница — это таблица в [`Src/panel_pages.c`](Src/panel_pages.c), одна строка на прибор:

```c
/* type       x    y    w    h   label       unit   min   max  warn alarm dec ch color */
{ W_GAUGE,   10,  50, 145, 140, "PRESSURE", "BAR",    0,  100,   70,   85, 1,  0, 0 },
```

- `min/max/warn/alarm` — тоже в десятых; `warn` — жёлтый, `alarm` — красный; `OFF` — без порога.
- `dec` — знаков после точки на экране (0 или 1).
- Типы: `W_GAUGE` (стрелочный), `W_DIGITAL` (цифровой), `W_SLIDER` (ползунок), `W_VBAR`
  (столбик), `W_LAMP` (лампа), `W_BUTTON` (кнопка).
- Рабочая область: y = 50…428 (выше — заголовок, внизу слева — heartbeat-квадрат 40×40 в (20, 434)).
- Шрифт — 5×7 из драйвера: цифры, латиница, `. : - / ! # % + = < >`. Кириллицы нет.

## Файлы

| Файл | Что это |
|---|---|
| `Inc/panel.h` | Публичный API: `Panel_DrawPage()`, `Panel_Poll()`, `Panel_SetChannel()`. |
| `Inc/gfx.h`, `Src/gfx.c` | Графика поверх `ST7796S_FillRect()`: линии с толщиной, окружности, дуги, скруглённые прямоугольники, текст по центру. Только целочисленная математика (таблица синусов), без libm и float. |
| `Src/panel.c` | Движок: рисует статическую часть прибора один раз, затем перерисовывает только изменившееся (стрелку, цифры, бегунок). |
| `Src/panel_pages.c` | Раскладка обеих страниц + демо-данные + реальный аптайм. |
| `Src/panel_internal.h` | Описание прибора (`Widget`), общее для `panel.c` и `panel_pages.c`. |

Связь с остальным: `Display/Src/tft_app.c` вызывает `Panel_DrawPage()` при переходе на
страницу и `Panel_Poll()` в каждом проходе главного цикла, пока страница на экране.
Panel использует из `Display/` только драйвер `st7796s.h`.

## Производительность (замерено на плате, SPI 10 МГц)

| Действие | Время |
|---|---|
| Полная отрисовка страницы (при переключении) | REMOTE ~650 мс, LOCAL ~610 мс |
| Одно обновление: стрелка, цифры, ползунок, лампа | 1–10 мс |
| Одно обновление: кнопка (меняет состояние только при нажатии) | ~24 мс |

`Panel_Poll()` перерисовывает **не больше одного прибора за вызов**, так что Ethernet не
блокируется надолго. Времена в таблице сняты на 10 МГц; сейчас SPI3 работает на 20 МГц
(потолок для SPI3), так что они примерно вдвое меньше. Заливки от 256 пикселей идут через
DMA (DMA1 Stream5) и не держат процессор; мелкие заливки (текст, тонкие линии) по-прежнему
блокирующие — для них настройка DMA дороже самой передачи.

## Что решить (открытые вопросы)

1. **Формат данных от сервера** для REMOTE — предложение: строки `P1=37.5;SW2=1;LVL3=64`
   → `Panel_SetChannel()`.
2. **Органы управления** на LOCAL: сенсорный дисплей (XPT2046/FT6236 на том же SPI),
   физические кнопки/энкодер на свободных выводах, или только через веб-страницу.
   У текущего дисплея сенсора нет, физическая кнопка одна (листает страницы).
3. **Локальные сигналы**: сколько аналоговых входов (диапазон), дискретных входов,
   выходов (реле) — от этого зависят выводы платы и раскладка LOCAL.
4. **Состав приборов** на каждой странице.
